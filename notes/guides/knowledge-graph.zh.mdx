一堆笔记只有在彼此指向之后，才会变成一个知识体系。Grimoire 为此提供了三件
互相咬合的东西：你手写的**双链**、系统替你计算的**反向链接**，以及可以漫游的
**知识图谱**。卡片笔记（[[cards-are-text]]）同样活在这张图里。

## 双向链接

在任何笔记或卡片中写下双方括号链接：

```mdx
frontmatter 规则见 [[guides/authoring]]。
先从 [[guides/getting-started|快速上手]] 开始。
直接跳到 [[guides/authoring#frontmatter|frontmatter 那一节]]。
```

- `[[目标]]` —— 用 id、标题或文件名链接
- `[[目标|文字]]` —— 自定义链接文字
- `[[目标#标题]]` —— 落到某个小节

解析顺序是：显式的 `note:`/`card:` 前缀 → 精确 id → **唯一**的文件名、标题或
别名。出现歧义时绝不猜测——如果两篇笔记同名，这条链接会被报告为失效，让你
自己去消歧。规则本身写在 [[link-resolution]] 里。

<Callout type="tip" title="失效链接是看得见的">
无法解析的链接会以波浪下划线呈现，而不是悄悄消失；`bun run verify` 也会把每
一条都连同来源笔记一起列出来。
</Callout>

围栏代码块和 `` `行内代码` `` 里的链接会被原样保留，所以讲解语法本身永远不会
凭空造出一条边。

### 不写正文也能连线

一篇笔记可以直接从 frontmatter 加入图谱，这对索引页很方便：

```yaml
---
title: 阅读清单
links: [guides/authoring, engine-boot]
aliases: [参考书目]
---
```

`aliases` 同时给这篇笔记增加了额外的名字，`[[…]]` 也能解析到它。

## 反向链接

每一篇笔记和每一张卡片的末尾都有一块**关联**面板：它链接到谁、谁链接到它，
以及一张局部图谱。无需维护——这些都由构建站点的同一次扫描推导出来。

在笔记正文里，你也可以自己摆放这些部件：

```mdx
<Backlinks />          {/* 谁链接到这里 */}
<Links />              {/* 这篇笔记链接到谁 */}
<Backlinks of="engine-boot" />   {/* …换成别的条目 */}
```

## 图谱

`#/graph` 会画出整张图；只要存在至少一条边，侧边栏就会出现入口。拖拽平移、
滚轮缩放、点击节点即可打开。悬停某个节点时，与它无关的部分会淡出。

也可以把局部视图嵌进任何笔记：

```mdx
<Graph note="guides/authoring" depth={2} height={360} />
<Graph card="engine-boot" />
```

<Graph note="guides/knowledge-graph" depth={2} height={320} />

布局是确定性的——同样的笔记永远画出同样的图形，所以这张地图在每次访问之间
都保持可辨认。

## 卡片笔记

卡片是尺度的另一端：一个想法、一个名字、纯文本。它们放在 `cards/` 里，一个
文件就是一个卡组，每张卡片以自己的 YAML 块分隔——精确规则见 [[card-format]]。

```md
---
title: 启动流程
id: engine-boot
tags: [引擎, 运行时]
links: [guides/getting-started]
---

引擎读取配置、扫描笔记，然后提供服务。
```

在 `#/cards` 浏览它们，或者把筛选后的一组拉进任意笔记：

```mdx
<Cards tag="engine" columns={2} />
<Cards ids="engine-boot,card-format" expand />
```

<Cards tag="卡片" columns={2} />

卡片是图谱中平等的一员：它们可以链接笔记，笔记也可以链接它们，并在图谱中以
空心节点出现。

<Callout type="note" title="为什么要单独一个盒子？">
笔记是**文档**——它有章节、有图表、有论证。卡片是**论断**：值得命名并复用的、
最小的一块项目知识。把两者分开，长文档才不会把藏在里面的事实一并吞掉。
</Callout>
